# Production runtime

Build `docker build --target production -t ulaxys-service:review .`. Build inputs are pinned to registry-observed PHP 8.5 and Composer digests; Redis extension archive is versioned and SHA-256 verified. Update pins deliberately and test actual platform requirements; do not copy pins from a different PHP minor. OS packages are installed from the distribution's signature-verified repository; individual OS package versions are not locked, so rebuilds are not byte-for-byte identical.

The multi-stage build installs `composer.lock` with `--no-dev --no-scripts`, creates strict optimized autoloading, checks real platform requirements, generates OpenAPI 3 and runs `.docker/verify-openapi.php`. No build-time database, APP_KEY or Signature is required. No cached production configuration or secrets are baked in. `.dockerignore` excludes .env, auth files, local dependencies, tests and caches. The final stage copies only runtime roots, with read-only source and private writable cache/log directories. Composer and build tools stay out of the final stage.

The runtime is non-root on port 8080. Nginx listens on IPv4 only (`0.0.0.0:8080`), so it starts on hosts and kernels without IPv6. Container platforms reach it over IPv4, including dual-stack networks; IPv6-only networks are not supported without an explicit change. Nginx serves only public files and the front controller; PHP-FPM listens on loopback. Supervisor manages both children and forwards graceful shutdown; exhausted child startup retries force a nonzero container exit through its event listener. Allow at least 160 seconds for shutdown. Worker memory is 256 MiB with up to eight workers: provision container memory accordingly.

Inject secrets at runtime, outside the checkout/image. Runtime validation runs before Laravel cached config can mask unsafe environment values. Require APP_ENV=production, APP_DEBUG=false, LOG_CHANNEL=stderr, a valid AES-256-CBC APP_KEY, nonempty SERVICE_SIGNATURE and PostgreSQL identity settings. Entrypoint generates runtime config cache, never keys, migrations or documentation. Explicit release migrations are a separate approved deployment operation.

Application logs use JSON stderr with secret-redacting Monolog processing. Nginx access logs omit query strings, headers and referrers. PHP excludes arguments from exception traces. Never intentionally log secrets or whole request objects. External observability collects container streams; no transport framework is added.

HEALTHCHECK validates local HTTP liveness. Configure database readiness separately against `/healthCheck/postgresStatus`; an unavailable database must not cause liveness restart loops. Connection establishment should be bounded by `PGCONNECT_TIMEOUT` (default image value 5). Keep all service/probe access on approved private networks. PostgreSQL and optional Redis are external services, never subprocesses inside this image.

For managed TLS proxies, the Dockerfile supports an optional `proxy_ca` BuildKit secret at `/etc/ssl/certs/ca-certificates.crt`; supply your trusted combined CA bundle and standard proxy build arguments. Do not disable TLS, package signatures or archive verification. No proxy addresses or CA secrets are committed. Production builds and actual-container smoke tests are required before release; see verification evidence for what ran in this PR.

The optional Redis queue uses synchronous dispatch by default. If enabled, run workers as a separately supervised deployment process and explicitly configure failed-job persistence/retry monitoring for that service; no queue workers or failed-job tables are included in this domain-free HTTP template.
